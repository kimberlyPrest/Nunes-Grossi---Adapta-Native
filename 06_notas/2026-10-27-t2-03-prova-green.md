## Defeito de mensagem encontrado (fora do CA, mas confunde o teste)

`OportunidadeDetalhes.tsx` passa `status="error"` para o `PageStateLayout`, que então mostra **dois
discursos contraditórios na mesma tela**: o título "Oportunidade não encontrada / você não tem
acesso" (correto) e, abaixo, um card vermelho "Houve uma instabilidade temporária" com botão
"Tentar novamente" (errado — não é instabilidade, é falta de permissão).

Causa: o componente tem estados separados (`empty` = sem acesso, `error` = falha técnica) e a página
usa `error` para os dois casos. Para um colaborador sem acesso, a tela sugere que ele tente de novo,
o que nunca vai funcionar.

**Correção proposta:** quando a falha for ausência de dados/permissão, usar `status="empty"` com a
mensagem de acesso; reservar `status="error"` para erro real de rede/banco. Não implementado nesta
task — é mudança de apresentação em mais de uma tela, melhor registrar como ajuste próprio para não
ampliar o recorte da T2.03.

## Lacuna de prova que permanece

O teste provou que a **ficha** não abre. A prova de que o **arquivo** não é baixável por quem tem o
caminho exige uma sessão real de um usuário ativo (a API sem sessão nega por outro motivo: não há
JWT de usuário). Duas formas de fechar:

1. SQL editor com `SET LOCAL ROLE authenticated` + `request.jwt.claims` do colaborador Seguros,
   avaliando `pode_ver_oportunidade(<opp de Saúde>, <uuid dele>)` → esperado `false`;
2. validação no próprio app, com um usuário que tenha acesso a uma oportunidade de Seguros
   (regressão: o download dele continua funcionando com link de 5 min).
